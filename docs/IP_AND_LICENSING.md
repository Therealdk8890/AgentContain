# Intellectual Property and Licensing

## Open-source license

WarrantKit is licensed under the Apache License, Version 2.0. The authoritative license text is in the repository's `LICENSE` file.

The Apache-2.0 license permits broad use, modification, distribution, and commercial use of the licensed work, subject to its terms. The license also provides the patent grant described in Section 3.

WarrantKit's open-source license is intentional. The project is not relying on restrictive licensing as its primary differentiation.

## What this document does

This document records the project's **current repository-level licensing and provenance posture**. It is not a legal opinion, an assignment of copyright, or a substitute for agreements with employees, contractors, companies, or contributors.

Ownership of particular intellectual property depends on the facts and agreements applicable to the person or entity that created it.

## Contribution provenance

For every material contribution, maintainers should be able to establish:

- who contributed it;
- that the contributor had the right to submit it;
- what third-party material, if any, it incorporates;
- what license applies to that contribution;
- whether any separate agreement governs the contribution.

The repository's Git history, pull requests, review records, and contribution documentation are part of that provenance record.

## Third-party material

Third-party code and content must retain required attribution and license notices. A contribution must not silently import material with incompatible licensing terms.

Where a dependency or copied material carries additional notice obligations, those obligations should be documented in the repository before release.

## Commercial platform boundary

The Apache-2.0 license applies to the material that is actually distributed in this repository. It does **not** grant rights to separately maintained code, hosted services, trademarks, customer data, private operational systems, or other assets that are not part of this repository merely because they interact with WarrantKit.

The project may evolve an open foundation and separate commercial offerings over time. Any future proprietary component should be maintained in a clearly separated repository or distribution boundary with its own ownership and licensing records.

Nothing in this document changes the Apache-2.0 license for the code that is already licensed under it.

## Trademarks

Apache-2.0 does not grant trademark rights. Use of the WarrantKit name or other project marks should not imply endorsement or affiliation without permission.

## Acquisition and diligence readiness

For future investment, partnership, or acquisition diligence, the project should maintain a clean record of:

- repository copyright and license notices;
- contributor provenance;
- employee/contractor IP agreements, where applicable;
- third-party dependency licenses;
- material third-party notices;
- separation between open-source and separately proprietary assets;
- security-sensitive external components and their licenses.

This repository-level record is intended to make that diligence easier, not to claim that all legal diligence is complete.

## Changes to this policy

Changes to licensing, contribution terms, or the open/commercial boundary should be reviewed deliberately and documented in the repository history. The Apache-2.0 license should not be changed casually after third-party contributions have been accepted.
